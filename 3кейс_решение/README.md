# Синаптик. Продуктовые гипотезы

## Гипотеза 1. Большинство покупателей сначала пробуют триал

Я связал платежи и подписки с заказами по `order_id`. Покупкой считал заказ со статусом `paid` без признака триала, если по нему есть завершённая транзакция на сумму больше нуля. Начало триала взял из даты создания подписки, связанной с оплаченным пробным заказом того же аккаунта. У каждого аккаунта использовал первую найденную покупку и первый найденный триал.

Из **19 283 покупателей** у **12 437 (64,5%)** первая покупка была после начала триала. Гипотеза подтвердилась для этой выгрузки. У остальных **6 846 покупателей (35,5%)** к первой оплате ещё не было записи о триале. Из них 6 701 вообще не имели такой записи, а 145 взяли триал после покупки.

У тех, кто сначала взял триал, медиана времени до покупки составила **около трёх суток**. У 10 570 из 12 437 таких покупателей оплата пришла между третьими и четвёртыми сутками, то есть примерно у 85%.

В настройках пробный период длится трое суток. Платёж в это время может быть автопродлением. Результат показывает, когда прошла оплата. По нему нельзя узнать, в какой момент пользователь решил купить подписку. В таблице подписок нет записей по бесплатному тарифу Basic, поэтому длительность пользования самим бесплатным тарифом здесь посчитать нельзя.

## Гипотеза 2. После триала на том же мобильном устройстве иногда появляется второй пробный аккаунт

Из таблицы устройств я взял мобильные записи с заполненными идентификаторами устройств и аккаунтов. Оставил коды в формате UUID и проверил коды, которые встречаются ровно у двух аккаунтов. Это нужно, потому что часть значений встречается у очень большого числа аккаунтов. Для каждой пары сравнил даты первого подтверждённого триала на двух аккаунтах. Интервал от трёх до семи суток выбран как признак того, что второй триал начался вскоре после окончания первого.

Нашёл **3 047** мобильных кодов, связанных ровно с двумя аккаунтами. У **106** таких кодов триал был у обоих аккаунтов. Для **10 кодов** второй триал начался через 3–7 суток. Получилось **9 разных пар аккаунтов**, потому что одна пара встретилась с двумя кодами.

В выгрузке есть случаи, похожие на повторный триал. Совпадение кода и близкие даты дают основание проверить эти пары вручную. Код может быть общим, а телефоном могут пользоваться разные люди. Время использования устройства в таблице заполнено одинаковым служебным значением, поэтому устройство нельзя привязать к точному моменту активации триала.

## Как повторить расчёт

Скачайте `orders.csv`, `transactions.csv`, `subscribe.csv` и `devices.csv`. Положите их в папку `data` рядом с `analyze.py`. Запустите `python3 analyze.py`. Скрипт выведет сводные числа без идентификаторов клиентов. Для запуска достаточно Python 3. [Исходная выгрузка](https://disk.yandex.ru/d/UYuFNCrHvWR3DQ)
